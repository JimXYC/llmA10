\subsection*{1.1.A}

\subsection*{1.1.B}
The perplexity on the 2048-token set is higher (137.58 versus 39.93). This is consistent with a mismatch between training and evaluation context lengths. During training, the model sees positions 0--511 and relative attention distances up to 511. Evaluation at length 2048 introduces larger positions and relative distances that were not represented in training. Although rotary position embeddings (RoPE) can be evaluated at these positions, the learned attention patterns need not extrapolate reliably. The additional context therefore does not guarantee lower perplexity for a model trained only at length 512. Continuing training at length 2048 would expose the model to the longer-range attention patterns used at evaluation.

\subsection*{1.2.C}
The perplexities are similar across the two attention backends. FlashAttention computes the same mathematical attention operation, while floating-point reduction order and low-precision rounding can change individual updates and the resulting training trajectory. The much higher 2048-token perplexity persists because both models were trained only at length 512.

Flash training was 1.63 times as fast, reducing measured runtime by 38.7\%. Peak allocated training memory fell by 26.2\%.

The full-run device high-water mark was higher (15,654 versus 14,456 MiB), with the flash peak occurring at the end of the run. This measure includes \href{https://docs.pytorch.org/docs/2.4/notes/cuda.html#memory-management}{unused allocator blocks} and covers final evaluation, while the training tensor-allocation peak is captured beforehand.

FlashAttention tiles Q/K/V computation and performs online softmax using on-chip memory, avoiding the storage of a complete sequence-by-sequence attention matrix in GPU global memory. During backpropagation it recomputes attention intermediates from these tiles. This reduces attention-intermediate memory and global-memory traffic. Attention arithmetic remains quadratic in sequence length. FlashAttention-2 also improves GPU occupancy and work partitioning while reducing non-matmul work and inter-warp communication. These mechanisms explain potential speed and memory gains; other model operations and runtime overhead limit the end-to-end improvement. See \href{https://arxiv.org/abs/2205.14135}{Dao et al. (2022)} and \href{https://arxiv.org/abs/2307.08691}{Dao (2023)}.
